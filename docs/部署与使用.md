# 部署与使用

## 1. 后台部署（局域网）

### 环境要求

- Python 3.10+
- 局域网内常开的一台电脑（Mac / PC / NAS）

### 启动步骤

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8080
```

查看本机 IP：

```bash
# macOS
ipconfig getifaddr en0
```

假设得到 `192.168.1.100`，Docker 启动后 Web 管理地址为：

```text
http://192.168.1.100:8080/sms/
```

若服务器已有 Nginx 占用 80/443，Docker 映射 `8080:8080`（或 `0.0.0.0:8080:8080`），Nginx 仍反代到 `http://127.0.0.1:8080`（见 `docs/nginx-makemoneies.top.conf`）。

首次访问输入 `SMS_ADMIN_TOKEN` 对应的管理口令，登录后通过 Cookie 维持会话，无需在 URL 传参。

### 安全建议

- 仅在内网使用，不要映射到公网
- 修改默认管理口令：

```bash
export SMS_ADMIN_TOKEN=请改成复杂口令
uvicorn main:app --host 0.0.0.0 --port 8080
```

- SQLite 文件位于 `backend/data/sms.db`，注意文件权限

### Docker 开机自启（阿里云 Linux / Ubuntu）

**1. Docker 服务随系统启动**

```bash
sudo systemctl enable docker
sudo systemctl start docker
```

**2. 容器自动拉起**

`docker-compose.yml` 已配置 `restart: unless-stopped`，Docker 启动后会自动恢复上次在运行的容器。

首次部署后先执行一次：

```bash
cd SMSReciver
docker compose up -d --build
```

**3.（推荐）整机重启后自动执行 compose**

```bash
# 编辑 docs/systemd/sms-receiver.service 里的 WorkingDirectory 为实际路径
sudo cp docs/systemd/sms-receiver.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable sms-receiver
sudo systemctl start sms-receiver
sudo systemctl status sms-receiver
```

验证：`sudo reboot` 后执行 `docker compose ps`，应看到 `sms-receiver` 为 `Up`。

## 2. Android 客户端配置

### 安装

1. Android Studio 打开 `android/`
2. 连接手机，Run 安装 APK

### 首次配置

1. 填写服务器地址，例如 `http://192.168.1.100`（Docker 默认映射 80 端口）
2. 填写设备名称（如「备用机-1」）和手机号（可选）
3. 点击「测试连通」确认网络可达
4. 点击「注册设备」
5. 授予短信、通知权限
6. 点击「启动转发服务」
7. 按提示关闭电池优化

### 常见问题

| 现象 | 处理 |
|------|------|
| 收不到短信上报 | 检查短信权限、前台服务是否在运行 |
| 服务被杀 | 关闭电池优化，允许后台运行 |
| 连不上后台 | 确认手机与电脑在同一 Wi-Fi，防火墙/安全组放行 80 |
| 读不到手机号 | 正常，系统以 `device_id` 标识设备 |

## 3. Web 管理页

### 功能

- 首页展示所有设备及最新短信
- 点击设备卡片进入单设备短信流
- 自动提取 4–8 位验证码，点击可复制
- 每 30 秒自动刷新
- 支持关键字搜索

### 访问方式

```text
http://<局域网IP>/sms/
```

或使用域名（示例）：

```text
https://makemoneies.top/sms/
```

脚本/接口调用时在请求头携带：`X-Sms-Token: <你的口令>`

## 4. 联调脚本

后台运行中时：

```bash
./scripts/integration_test.sh
```

可通过环境变量指定地址：

```bash
BASE_URL=http://192.168.1.100:8080 ADMIN_TOKEN=admin123 ./scripts/integration_test.sh
```

## 5. 数据流

```text
短信 -> Android SmsReceiver -> SmsForwardService -> POST /api/sms/inbound -> SQLite -> Web 页面
```

失败时会进入本地待发送队列，服务恢复后自动重试。

## 6. API 接口文档

验证码接收后台 REST API 说明。

### 基础信息

| 项目 | 说明 |
|------|------|
| 基础地址（HTTPS） | `https://makemoneies.top` |
| 基础地址（直连 Docker） | `http://123.56.133.92:8080` |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |

> API 路径均以 `/api/` 开头。通过 Nginx 部署时，请使用域名根地址，不要加 `/sms/` 前缀。

### 鉴权方式

#### 管理端鉴权（查询接口）

用于 `GET /api/devices`、`GET /api/sms`。

| 方式 | 说明 |
|------|------|
| Cookie | 浏览器登录 `/sms/login` 后自动携带 `sms` Cookie |
| 请求头 | `X-Sms-Token: {管理口令}` |

管理口令对应环境变量 `SMS_ADMIN_TOKEN`，默认 `admin123`。

未授权时返回 `HTTP 401`：`{"detail": "Unauthorized"}`

#### 设备端鉴权（短信上报）

用于 `POST /api/sms/inbound`。

| 请求头 | 必填 | 说明 |
|--------|------|------|
| `X-Device-Id` | 是 | 设备 UUID，注册时返回 |
| `X-Api-Key` | 是 | 设备密钥，注册时返回 |

鉴权失败时返回 `HTTP 401`：`{"detail": "Invalid device credentials"}`

### 接口列表

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/health` | 无 | 健康检查 |
| POST | `/api/devices/register` | 无 | 注册设备 |
| GET | `/api/devices` | 管理端 | 查询设备列表 |
| POST | `/api/sms/inbound` | 设备端 | 上报短信 |
| GET | `/api/sms` | 管理端 | 查询短信列表 |

### 6.1 健康检查 `GET /api/health`

**请求参数：** 无

**返回值：**

```json
{
  "status": "ok"
}
```

```bash
curl https://makemoneies.top/api/health
```

### 6.2 注册设备 `POST /api/devices/register`

**请求头：** `Content-Type: application/json`

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| device_name | string | 是 | 设备名称，1~100 字符 |
| phone_number | string | 否 | 手机号，可填多个（如双卡） |

**请求示例：**

```json
{
  "device_name": "双卡机-主号",
  "phone_number": "13800138000,13900139000"
}
```

**返回值：**

| 字段 | 类型 | 说明 |
|------|------|------|
| device_id | string | 设备唯一 ID |
| api_key | string | 设备密钥 |
| device_name | string | 设备名称 |
| phone_number | string \| null | 手机号 |

```json
{
  "device_id": "c50212d4-7925-4772-bc65-f57d3d70e977",
  "api_key": "RzGi4QgokjaW8Pukdpg1fYrtLzQZJcog",
  "device_name": "双卡机-主号",
  "phone_number": "13800138000,13900139000"
}
```

### 6.3 查询设备列表 `GET /api/devices`

**请求头：** `X-Sms-Token: {管理口令}` 或登录 Cookie

**Query 参数：** 无

**返回值：** 数组，每项字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| device_id | string | 设备 ID |
| device_name | string | 设备名称 |
| phone_number | string \| null | 手机号 |
| last_seen_at | string \| null | 最近上报时间 |
| latest_sms_preview | string \| null | 最新短信预览 |
| latest_sms_at | string \| null | 最新短信时间 |

### 6.4 上报短信 `POST /api/sms/inbound`

**请求头：**

| 名称 | 必填 | 说明 |
|------|------|------|
| Content-Type | 是 | `application/json` |
| X-Device-Id | 是 | 注册返回的 device_id |
| X-Api-Key | 是 | 注册返回的 api_key |

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sender | string | 是 | 发件号码，1~50 字符 |
| body | string | 是 | 短信全文 |
| received_at | string | 是 | 收到时间，建议 ISO 8601 |
| phone_number | string | 否 | 本机手机号 |

**返回值：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | integer | 短信记录 ID |
| verification_code | string \| null | 自动提取的验证码 |
| duplicate | boolean | 是否重复上报 |

```json
{
  "id": 1,
  "verification_code": "123456",
  "duplicate": false
}
```

### 6.5 查询短信列表 `GET /api/sms`

**请求头：** `X-Sms-Token: {管理口令}`

**Query 参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| device_id | string | 否 | - | 按设备筛选 |
| keyword | string | 否 | - | 搜索内容/发件人/验证码 |
| limit | integer | 否 | 50 | 每页条数，1~200 |
| offset | integer | 否 | 0 | 偏移量 |

**返回值：**

| 字段 | 类型 | 说明 |
|------|------|------|
| total | integer | 总条数 |
| items | array | 短信列表 |
| items[].id | integer | 短信 ID |
| items[].device_id | string | 设备 ID |
| items[].device_name | string \| null | 设备名称 |
| items[].sender | string | 发件人 |
| items[].body | string | 短信内容 |
| items[].received_at | string | 手机收到时间 |
| items[].created_at | string | 服务器入库时间 |
| items[].verification_code | string \| null | 验证码 |

### 6.6 错误码

| HTTP 状态码 | 场景 |
|-------------|------|
| 200 | 成功 |
| 401 | 口令或设备凭证错误 |
| 404 | 资源不存在 |
| 422 | 参数格式错误 |
